# GymFinder Алматы — сайт и PostgreSQL

## Запуск сайта

Нужны Node.js 22.13+ (проверено на 24.12), PostgreSQL и npm. В Windows с PostgreSQL 18 по стандартному пути:

```powershell
npm ci
npm run site:start
```

Откройте **http://127.0.0.1:3000**. Скрипт запуска поднимает базу, собирает сайт при отсутствии сборки и запускает `next start` в фоне. Повторный запуск не создаёт ещё один сервер. Для сборки после изменения исходников выполните `npm run build`. `npm run dev` предназначен для редактирования исходников; обычный просмотр использует готовую сборку. Скрипт `db:setup` создаёт отдельный локальный кластер на порту 55443, загружает SQL-кейс при первом запуске и применяет миграции сайта и сроков абонемента. Повторный запуск сохраняет данные. Путь к бинарным файлам другой версии задаётся переменной `PG_BIN`. Настройки подключения сохраняются в `.env.local`; файл не включён в архив. Сервер сайта использует роль БД с доступом к данным без прав DDL.

Каталог, фильтры, карта, сравнение, регистрация, избранное, отзывы, помощник и SQL-витрина работают с PostgreSQL. Краткое руководство пользователя находится на странице `/guide`. Помощник поддерживает Gemini с инструментами сайта; при недоступности API работает локальный режим. Откройте «Войти» → «Создать аккаунт», чтобы проверять избранное и отзывы. Учебные клиенты SQL-кейса не являются аккаунтами сайта.

Каталог по умолчанию ставит тарифы с опубликованной ценой перед учебными оценками. Карта загружает все подходящие залы, а близкие маркеры объединяет; три зала без проверенной точки на ней не показываются. Перед открытием сравнения выбранные залы заново проверяются по текущей категории, сроку, бюджету и другим фильтрам, поэтому старые цены не переносятся между условиями поиска.

Для поиска поблизости нажмите «Найти залы рядом» и разрешите геолокацию браузеру. Выберите радиус от 1 до 20 км; каталог отсортирует найденные залы по расстоянию, а карта покажет ваше положение и радиус. Три места без проверенных координат не участвуют. Координаты не добавляются в ссылку страницы и не передаются Gemini; запрос поиска использует их для вычисления расстояний.

Gemini: `GEMINI_API_KEY` и `GEMINI_MODEL` задаются только на сервере в `.env.local`. Страница http://127.0.0.1:3000/settings/ai доступна при открытии сайта через localhost и проверяет ключ перед сохранением в серверный `.env.local`. Команды: «Найди студенту до 20к», «Сравни первый и третий», «Покажи карту», «Добавь этот зал в избранное», «Подготовь отзыв». Публикация отзыва требует кнопки подтверждения. Подробности и результат живой проверки — `docs/GEMINI_ASSISTANT.md`. Принудительный локальный режим — `AI_PROVIDER=local`. По умолчанию используется `gemini-3.5-flash-lite`; если Google временно перегружен, чат показывает локальный ответ и причину. Для повторной проверки: `npm run test:ai:live` (рекомендации с фильтрами и сравнение), `npm run test:ai:actions` (временный QA-аккаунт, избранное и отмена черновика отзыва) и `npm run test:ai:terms` (живой запрос на два месяца и сравнение с сохранением срока). Эти команды обращаются к Gemini и расходуют квоту проекта.

Проверки: `npm run typecheck`, `npm run lint`, `npm test`, `npm run test:api` (при запущенном сайте), `npm run build`. После `npm run db:setup` выполните `npm run test:terms`: это проверка поиска и сравнения новых сроков на реальной базе для трёх категорий. Production-запуск: `npm run build`, затем `npm start`. API-проверка создаёт и удаляет только свой временный аккаунт в локальной тестовой базе.

Для уже загруженной базы SQL-кейса примените миграции `003`–`006` по порядку, затем укажите `DATABASE_URL` и точный `APP_ORIGIN` в `.env.local`. Если миграции `003`–`005` уже выполнены, достаточно `006`: она обновляет прямые ссылки и координаты залов, сохраняя тарифы и аккаунты. При смене адреса сайта обновите `APP_ORIGIN`.

## SQL-кейс

Учебный SQL-кейс по файлу `SQL ++ (1) (1).docx`. В нём 10 связанных таблиц PostgreSQL, **2460 строк** после загрузки, минимум 70 строк в каждой таблице. Названия и адреса 70 залов взяты из опубликованных каталогов. Все клиенты, тренеры, занятия, платежи, бронирования, отзывы и удобства являются **синтетическими тестовыми данными**.

## Запуск

Нужны PostgreSQL 16+ и `psql`. Из этой папки:

```powershell
createdb -U postgres gymfinder_almaty
psql -U postgres -d gymfinder_almaty -v ON_ERROR_STOP=1 -f run_all.psql
psql -U postgres -d gymfinder_almaty -v ON_ERROR_STOP=1 -f db/queries/assignment_queries.sql
psql -U postgres -d gymfinder_almaty -v ON_ERROR_STOP=1 -f db/queries/dml_demo.sql
```

Если сервер не на стандартном порту, добавьте `-h` и `-p`. `run_all.psql` загружает учебный набор и включает миграции 005 и 006. Для обновления работающего сайта с сохранением данных используйте `npm run db:setup` или отдельно примените недостающие миграции.

## Состав

- `db/migrations/001_schema.sql` — таблицы, PK/FK/UNIQUE/CHECK.
- `db/migrations/002_views_indexes.sql` — индексы и представления `v_gym_prices`, `v_zone_summary`.
- `db/seed/10_real_gyms.sql` — реальные названия и адреса 70 залов, URL источника у каждой строки.
- `db/seed/20_demo_activity.sql` — исходные месячные/годовые тарифы и связанные тестовые действия.
- `db/migrations/005_subscription_terms.sql` — 840 учебных вариантов на 2, 3, 6 и 9 месяцев, идемпотентное добавление к существующей базе.
- `db/migrations/006_verified_venues.sql` — прямые страницы 70 залов, координаты из источников для 67 и отметка 3 непроверенных точек.
- `db/checks/verify.sql` — проверка объёма и согласованности данных.
- `db/queries/assignment_queries.sql` — SELECT/WHERE/ORDER BY, 8 JOIN, 5 подзапросов, GROUP BY/HAVING/COUNT/SUM/AVG и VIEW.
- `db/queries/dml_demo.sql` — по 2 INSERT/UPDATE/DELETE в откатываемой транзакции.
- `docs/er-diagram.mmd` — ER-диаграмма.
- `docs/SOURCES_AND_LIMITS.md` — происхождение данных и ограничения достоверности.

## Цены и геолокация

Сегменты `student`, `adult`, `premium` — учебные варианты тарифов. **1046 из 1060 цен** являются модельными оценками, а не предложениями клубов. Только 14 цен помечены `published`: 10 годовых тарифов Invictus, 2 месячных тарифа «Тастак» и 2 месячных тарифа First Fitness «Таугуль». Поля `price_basis`, `price_source_url`, `price_checked_on` позволяют их различать. Средняя цена в SQL-запросах — среднее **по этому учебному набору**, а не рыночная статистика Алматы.

Сроки в каталоге: 1, 2, 3, 6, 9 месяцев, год и любой срок. Новые 2/3/6/9 месяцев равны 60/90/180/270 дням. Их стоимость — базовая 30-дневная цена × число месяцев, без придуманных скидок. Все 840 новых вариантов помечены `model_estimate` с `price_source_url=NULL`, даже если исходная месячная цена опубликована; наличие такого абонемента у клуба не подтверждено. Бюджет и сравнение остаются в расчёте за 30 дней, отдельно показывается полная стоимость. Расширение проверено: 61 из 61 модульного теста, ESLint и production build прошли; реальная SQL-проверка охватила все 12 сочетаний категории и нового срока. Живой Gemini нашёл двухмесячные тарифы и сравнил первый и третий с сохранением 60 дней.

Прямые страницы всех 70 залов были доступны на дату проверки 10.11.2026. Для 67 залов координаты взяты со страницы конкретного клуба (`geo_accuracy_m=1000` как ориентировочная отметка, не измеренная точность); их адреса не геокодировались независимо. У 3 залов исходные точки вышли за допустимую область схемы — старые приблизительные координаты оставлены с `geo_accuracy_m=8000`, они скрыты с карты и исключены из сортировки по расстоянию. Перед поездкой сверяйте адрес по ссылке источника.

`city_zone` для 67 залов пересчитана по простым порогам широты и долготы. Это ориентировочные части города, а не официальные административные границы. Файл `gymfinder-almaty-database.sql` содержит экспорт учебной схемы `almaty_gym`; аккаунты и переписка пользователей сайта в него не включены.

Все скрипты используют отдельную схему `almaty_gym`, поэтому не меняют более ранний проект GymFinder KZ в схеме `public`.
